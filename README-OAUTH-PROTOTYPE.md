# Прототип Яндекс OAuth + общая папка Диска

Этот прототип не переносит настоящие контакты. Он проверяет, могут ли два разных Яндекс-аккаунта через REST API читать и изменять один файл в общей папке `Справочник контактов`.

## Уже настроено

В `.env.local` указан публичный Client ID и локальный Redirect URI:

```env
VITE_YANDEX_CLIENT_ID=46564f36ea254c5da1a7717f0225a625
VITE_YANDEX_REDIRECT_URI=http://localhost:5173/auth/callback
```

`.env.local` не попадёт в Git. Client Secret приложению не нужен и нигде не используется.

## Запуск

```bash
npm install
npm run dev
```

Откройте именно:

```text
http://localhost:5173/oauth-test
```

Не используйте сетевой IP и `127.0.0.1`, потому что в Яндекс OAuth зарегистрирован Redirect URI через `localhost`.

## Последовательность проверки

### Аккаунт владельца папки

1. Нажмите `Войти через Яндекс`.
2. Выберите аккаунт владельца папки.
3. Подтвердите права.
4. Нажмите `Проверить доступ к папке`.
5. Нажмите `Создать файл`.
6. Нажмите `Прочитать файл`.

На Диске должен появиться файл:

```text
Справочник контактов/contacts-api-test.json
```

### Второй аккаунт

1. Нажмите `Выйти на этом устройстве`.
2. Снова нажмите `Войти через Яндекс`.
3. Выберите приглашённый аккаунт с правом редактирования общей папки.
4. Проверьте папку.
5. Прочитайте файл.
6. Нажмите `Изменить файл`.

### Повторная проверка владельцем

1. Выйдите и снова войдите владельцем.
2. Нажмите `Прочитать файл`.
3. Проверьте, что `revision` увеличилась, а в `updatedBy.login` указан второй аккаунт.

## Что прислать при ошибке

Скопируйте строку из журнала проверки вместе с HTTP-кодом и названием ошибки. OAuth-токен присылать нельзя.

Полезные примеры:

```text
DiskNotFoundError (HTTP 404)
DiskPathPointsToExistentDirectoryError
ForbiddenError (HTTP 403)
UnauthorizedError (HTTP 401)
```

## Безопасность прототипа

- Client Secret отсутствует.
- PKCE использует `S256`.
- OAuth `state` проверяется перед обменом кода на токен.
- Токен хранится только в `sessionStorage` текущей вкладки.
- В тестовом файле нет настоящих контактов.
- Удаление перемещает тестовый файл в корзину, а не удаляет навсегда.

Это технический тест. Для рабочей версии отдельно будут реализованы шифрование базы, список разрешённых пользователей, резервные копии, офлайн-очередь и разрешение конфликтов.
